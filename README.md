# Mochi AI Chat v2.1 - 商用AI角色聊天平台

一款治愈系AI角色聊天平台，对标星野AI移动端交互体验，支持自定义角色、社区分享、个性装扮、用户系统、云端同步等功能。

**v2.1 重大更新**：替换 SQLite 为纯JS JSON文件存储，**零编译依赖**，支持 Render/Vercel 等平台直接部署。

## ✨ 功能特性

### 👤 用户系统
- **注册登录**：用户名+密码注册登录，JWT token鉴权
- **个人资料**：昵称、头像、个人简介可自定义
- **自动登录**：token存储本地，刷新自动校验
- **数据隔离**：每个用户数据完全独立，互不影响

### 💾 云端存储
- **角色云端同步**：所有角色数据存在服务器，换设备也能看到
- **对话历史云端**：聊天记录永久保存，随时查看
- **交易记录可追溯**：每一笔充值消费都有详细记录

### 💰 米粒计费体系
- **按Token用量计费**：输入+输出token都计入，用多少扣多少
- **米粒兑换**：1000 token = 1 米粒（可配置）
- **新用户福利**：注册即送1000米粒（可配置）
- **实时扣费**：对话完成后按实际用量扣费

### 💳 支付系统
- **可插拔架构**：通过配置切换支付渠道
- **模拟支付**：内置mock模式，方便测试
- **微信/支付宝预留**：完整的接入框架和配置项
- **订单管理**：完整的订单生命周期管理

### 🎭 角色聊天
- **AI角色对话**：基于大模型的智能对话
- **流式输出**：SSE逐字渲染，打字机效果
- **角色人设**：自定义角色性格、语气、背景
- **多角色切换**：顶部滑动切换不同角色

### 🎨 角色管理
- **创建角色**：头像、名称、人设、简介、标签
- **编辑角色**：随时修改角色设定
- **删除角色**：一键删除，级联清理对话
- **公开/私密**：选择是否分享到社区

### 🌐 角色社区
- **社区广场**：浏览其他用户分享的角色
- **一键导入**：喜欢的角色一键导入到本地
- **搜索筛选**：按热度、时间、关键词搜索
- **点赞互动**：为喜欢的角色点赞

### 🎀 自定义装扮
- **页面UI自定义**：纯CSS覆盖，全局样式自由定制
- **聊天气泡自定义**：专属气泡样式，彰显个性
- **聊天壁纸自定义**：上传图片做背景，调节透明度模糊度
- **本地保存**：装扮配置存在本地，不丢失

### 📊 数据明细
- **米粒明细**：充值消费记录一目了然
- **充值记录**：所有订单状态可查
- **消费详情**：每笔对话的token用量明细

## 🚀 快速开始

### 环境要求
- Node.js >= 16.0.0
- 一个 OpenAI 兼容格式的 API 密钥

### 安装部署

```bash
# 1. 解压文件
unzip mochi-ai-chat-v2.1.zip
cd mochi-ai-chat

# 2. 安装依赖（零编译，纯JS）
npm install

# 3. 配置环境变量
cp .env.example .env
# 编辑 .env 文件，填入你的 API_KEY 和其他配置

# 4. 启动服务
npm start
```

服务启动后访问 http://localhost:3000 即可使用。

### 首次使用
1. 打开网站，点击「注册」创建账号
2. 注册成功自动登录，赠送1000米粒
3. 进入「角色」页面，创建你的第一个角色
4. 回到「聊天」页面，开始和角色对话
5. 或者去「社区」逛逛，导入别人分享的角色

## ⚙️ 配置说明

### 上游API配置
- `API_BASE_URL`：上游API基础地址（OpenAI兼容格式）
- `API_KEY`：上游API密钥（**仅存后端，前端不可见**）
- `DEFAULT_MODEL`：默认使用的模型
- `API_COST_PER_CALL`：上游单次调用成本价（用于成本核算）

### 服务器配置
- `PORT`：服务监听端口，默认3000
- `NODE_ENV`：运行环境 development/production

### JWT鉴权配置
- `JWT_SECRET`：JWT签名密钥（生产环境请修改为复杂随机字符串）
- `JWT_EXPIRES_IN`：Token过期时间（秒），默认7天

### 数据存储配置
- `DATA_DIR`：JSON数据文件存储目录，默认 `./data`

### 米粒计费配置
- `TOKENS_PER_RICE`：Token兑换比例，多少个token=1米粒，默认1000
- `NEW_USER_RICE`：新用户注册赠送初始米粒数，默认1000

### 充值档位配置
- `RECHARGE_TIERS`：充值档位，格式：`金额:米粒数:赠送米粒数,金额:米粒数:赠送米粒数`
- 默认档位：6:60:0, 30:300:30, 68:680:80, 128:1280:200, 328:3280:600, 648:6480:1500

### 支付配置
- `PAY_CHANNEL`：支付渠道，mock（模拟支付）/ wechat（微信支付）/ alipay（支付宝）
- 微信支付配置：WECHAT_APP_ID、WECHAT_MCH_ID、WECHAT_API_KEY、WECHAT_NOTIFY_URL
- 支付宝配置：ALIPAY_APP_ID、ALIPAY_PRIVATE_KEY、ALIPAY_PUBLIC_KEY、ALIPAY_NOTIFY_URL

### 社区配置
- `COMMUNITY_PAGE_SIZE`：社区单页加载数量，默认20

## 💾 数据存储说明

v2.1 版本使用 **JSON文件存储**，替代了之前的 SQLite 数据库，优势：

- **零编译依赖**：不需要 node-gyp，不需要 C++ 编译环境
- **零配置**：首次运行自动创建 data 目录和所有 JSON 文件
- **易备份**：直接复制 data 目录即可备份所有数据
- **易迁移**：拷贝 JSON 文件到任何服务器都能直接用
- **Render友好**：完美支持 Render 等 PaaS 平台直接部署

### 注意事项
- JSON 文件存储适合中小规模使用（万级用户以内）
- 如果用户量很大，建议升级到 MySQL/PostgreSQL 等专业数据库
- 定期备份 data 目录，避免数据丢失
- Render 的文件系统是临时的，重启会丢失数据。如果需要持久化，建议挂载持久化磁盘，或升级到云数据库

## 🔒 安全说明

1. **API密钥安全**：上游API密钥仅存在于后端 .env 文件，前端代码、请求参数、本地存储中绝对不会出现
2. **后端中转**：所有AI对话请求必须经由后端中转，前端不直接调用上游API
3. **密码加密**：用户密码使用 bcryptjs 加密存储，不可逆
4. **JWT鉴权**：所有接口需要 token 鉴权，用户数据完全隔离
5. **输入校验**：后端接口做好参数校验，防止恶意请求
6. **CSS安全**：用户自定义装扮仅允许纯CSS样式覆盖，禁止执行JavaScript
7. **XSS防护**：所有用户输入内容在前端渲染时进行HTML转义

## ☁️ 部署到生产环境

### Render 部署（推荐，零配置）

1. 将代码推送到 GitHub 仓库
2. 在 Render 上创建新的 Web Service
3. 连接你的 GitHub 仓库
4. 配置：
   - Build Command: `npm install`
   - Start Command: `npm start`
5. 在 Environment Variables 中添加你的配置（API_KEY、JWT_SECRET等）
6. 点击部署，等待完成

**注意**：Render 的文件系统是临时的，服务重启后 data 目录的数据会丢失。如果需要数据持久化，建议：
- 挂载 Render Disks 持久化磁盘
- 或者升级到云数据库方案

### Vercel 部署

1. 将代码推送到 GitHub
2. 在 Vercel 导入项目
3. 配置环境变量
4. 部署完成

### Docker 部署

```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install --production
COPY . .
EXPOSE 3000
CMD ["npm", "start"]
```

### 生产环境建议

1. **修改JWT密钥**：使用复杂随机字符串
2. **配置HTTPS**：使用 Nginx 反向代理，配置SSL证书
3. **进程守护**：使用 pm2 或 systemd 管理进程
4. **日志管理**：配置日志轮转，避免日志文件过大
5. **定期备份**：定期备份 data 目录
6. **限流防护**：配置 API 限流，防止恶意刷量

## 📈 升级说明

### v1.x → v2.0 重大变更
- 新增用户注册登录系统
- 数据从本地存储升级为云端存储
- 计费方式从按次改为按token用量
- 新增支付系统和订单管理
- 新增米粒体系

### v2.0 → v2.1 变更
- 替换 SQLite 数据库为纯JS JSON文件存储
- 移除 better-sqlite3 原生依赖，零编译
- 支持 Render/Vercel 等平台直接部署
- 新增 db.js 数据库模块，API兼容 better-sqlite3

### 数据迁移
v2.0 的 SQLite 数据无法直接迁移到 v2.1 的 JSON 存储，需要重新开始。如果需要迁移数据，可以编写脚本从 SQLite 导出再导入 JSON。
